## Summary

AIDA is a course about designing and building AI-driven applications. The course moves from basic concepts and portfolio setup through RAG, LLM APIs, code agents, specification-driven development, security, ethics, MCP, and a final team project. The common thread is that AI is treated as one component in a real software system rather than as a standalone chat window.

Building a useful AI product requires more than selecting a model. It involves understanding a problem, preparing data, defining expected behavior, integrating external services, testing uncertain outputs, protecting secrets, and deciding where human judgment is still needed. The course brings these concerns together in a practical sequence.

## Course progression

The teaching plan is organized as a gradual move from concepts to a complete application:

- **Foundations:** an introduction to AI-driven applications, LLMs, the course expectations, and the portfolio.
- **Grounded knowledge:** two sessions on RAG, document preparation, retrieval quality, prompts, and chatbot integration.
- **Application development:** code agents, LLM API calls, structured output, backend logic, and end-to-end implementation.
- **Development method:** specifications, acceptance criteria, theory building, agent-ready tickets, and team collaboration.
- **Responsible delivery:** secret management, security, privacy, bias, legal considerations, and human oversight.
- **Integration and presentation:** MCP, final project work, product demonstration, and oral examination preparation.

Each stage produces material for the portfolio, so the final collection documents both technical outcomes and the reasoning behind them.

## Key takeaways

AI development is still software development: architecture, requirements, testing, security, and communication remain essential. The newer skills involve providing useful context to a model, evaluating probabilistic output, and designing boundaries around what an AI component may do.

- AI should solve a clearly defined problem rather than be added for novelty.
- Model output needs evaluation because it can vary and appear confident when incorrect.
- Data preparation, prompts, and retrieval often matter as much as model choice.
- Human review remains important where output affects people or important decisions.

## Closing note

The course presents AI less as a special feature and more as another engineering material with distinct strengths and risks. A successful AI application depends at least as much on the surrounding system and workflow as it does on the model itself.
