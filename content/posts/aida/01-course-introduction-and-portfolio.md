## Summary

The first session introduces the course, its expectations, and the role of large language models in modern software architecture. It also establishes the portfolio as an ongoing record of the work. The practical task is to create and deploy a Hugo site, using the Blowfish theme as a starting point.

A portfolio turns individual exercises into a visible learning process. Writing about decisions and results makes it easier to see progress, explain technical choices, and prepare for the final examination. Starting with a static site also keeps the publishing workflow simple and repeatable.

## Session focus

The introductory session covers both the academic framework and the practical publishing setup:

- What an AI-driven application is and how an LLM can fit into a wider software architecture.
- The structure of the course, its expectations, and the connection between weekly exercises and the examination.
- Setting up a Hugo project and selecting the Blowfish theme as the visual foundation.
- Connecting the portfolio to GitHub and deploying it as a public website.
- Writing an initial article about expectations for AI in software development.

The intended output is a functioning portfolio that can be extended throughout the course with cases, implementation notes, and reflections.

## Key takeaways

A static site generator separates content, configuration, and presentation, making the publishing workflow easier to maintain. Project documentation is not an afterthought: it clarifies what was built, why choices were made, and what should improve next.

- Markdown keeps the course notes portable and easy to edit.
- Git provides a history of both the site and the learning process.
- Deployment turns local work into something that can be reviewed and shared.

## Closing note

AI can speed up research, implementation, and debugging, but it does not remove the need to understand the system. The portfolio can show that understanding rather than serving only as a gallery of finished outputs.
